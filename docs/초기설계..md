nestJs로 jobs를 관리하는 백엔드 시스템을 개발할꺼야.

크게 1. RESTful API로 작업을 생성·조회·검색하는 시스템(queue), 2. 백그라운드 작업을 통해 작업을 주기적으로 처리하는 시스템(worker)을 제작할꺼야.

두개다 하나의 레포에서 관리하되, 각각 실행시킬 수 있어야해. 즉, 데이터 저장은 1번과 2번의 모든 프로세스가 한곳에 저장하고 삭제하지만, 1번과 2번의 프로세스는 각각 중복해서 실행될 수 있어.



주요 기술스택

\- 프레임워크: NestJS (TypeScript)

\- 데이터 저장: `node-json-db`

\- 스케줄러: `@nestjs/schedule`



기본 데이터 구조

1\. jobs.json

{

&#x09;"jobs": \[

&#x09;	{ 

&#x09;		"id": "uuid", // pk로 식별값이야

&#x09;		"title": "lorem ipsum", // 랜덤텍스트(1000자제한)

&#x09;		"description": "lorem ipsum", // 랜덤텍스트(2000자제한)

&#x09;		"status": "create" | "pending" | "done", // 생성, 처리 대기중, 완료

&#x09;	}

&#x09;]

&#x09;workers: {{hex64}: datetimestemp} // 2번의 고유 id

&#x09;reaper: "" // 2번중 worker의 리스트를 들고, worker의 리스트안에 없다면 preemption를 초기화 + status를 pending에서 create로 롤백 시키는 역할

}

2\. "jobs의 아이디"-lock.json

{

&#x09;"preemption": hex64 // 현재 어떤 프로세스가 이 데이터를 누가 점유하고 있는지

&#x09;"preemptedAt": "2026-09-03T20:00:00.000Z" 

}

3\. jobs-global-lock.json

{

&#x09;"preemption": hex64 // 현재 어떤 프로세스가 업데이트를 점유하고 있는지

&#x09;"preemptedAt": "2026-09-03T20:00:00.000Z"

}

}

2\. 백그라운드 작업을 통해 작업을 주기적으로 처리하는 시스템(worker)을 제작할꺼야.

1\. 실행시 자신의 고유한 id(hex64)를 하나 생성하고, 해당 id를 프로세스 종료시까지 캐싱해놓고, 해당 데이터를 데이터구조의 worker에 등록하고 1분에 한번씩 datetimestemp를 갱신함.

2\. 실행시간으로 부터 60초가 지날때마다 reaper에 있는 uid로 worker의 datetimestemp를 체크함.

&#x20;2-1. 만약 해당 worker가 없을경우 자신의 id를 reaper에 등록하고, 1분후 조회해서 자신의 id가 reaper 정상등록되어있을경우 자신이 reaper가됨.

&#x20;2-2. 만약 해당 worker가 있지만 datetimestemp가 갱신된지 5분이 지났다면, 자신의 id를 reaper에 등록하고, 1분후 조회해서 자신의 id가 reaper 정상등록되어있을경우 자신이 reaper가됨.

&#x20;2-3. 만약 해당 worker가 있고, datetimestemp도 5분이내라면 reaper가 되기를 포기하고, 2번의 체크로직만을 돌림.

3\. 만약 내가 reaper라면

&#x09;3-1. "jobs의 아이디"-lock.json의 preemption값을 체크해서, 해당 preemption값이 worker에 없다면, 해당 preemption 값을 초기화하고, 해당 status도 'create'로 초기화함.

&#x09;3-2. worker에서 datetimeStemp가 갱신한지 6분이상 지난 id가 있다면 해당 데이터를 삭제함.

&#x09;3-3. jobs-global-lock.json이 있다면, 1분마다 체크해서, preemption이 worker리스트에 없을경우 삭제, preemptedAt이 5분을 넘겼을 경우 삭제한다.

4. 모든 worker는 1분마다 한번씩, jobs에서 현재 status가 create를 가져와서, 

"jobs의 아이디"-lock.json를 생성하고(반드시, await fs.open(lockPath, 'wx'); 사용),

4-1. 생성에 성공했다면, jobs-global-lock.json을 생성후 status를 'pending'으로 변경후, jobs-global-lock.json를 삭제하고, 1분동안 점유하고하고 있다가, jobs-global-lock.json를 생성후, status를 'done'로 변경하고  "jobs의 아이디"-lock.json와 jobs-global-lock.json를 삭제함.

4-2. 만약, 4-1에서 jobs-global-lock.json파일이 이미 있다면, 1초에 한번씩 해당 파일이 삭제되기를 대기한 후, 삭제가 되었다면 4-1을 수행함.

4-3. 생성에 실패했거나, 이미 lock파일이 있다면, 1분간 침묵후, 새로운 jobs를 가져와서 5번을 반복함.
